# Shortener 0.0.4

Лабораторная работа №4 по дисциплине «Методы и средства проектирования информационных систем и технологий».

Бездняков Александр, ИСТбд-42.

Оформлены пять страниц существующего сервиса: главная, форма, список, карточка и отказ. Интерфейс находится в приложении Flask и использует Jinja2 и Bootstrap 5.3.8. Функции и PostgreSQL 16 сохранены из третьей работы.

## Запуск

```text
Репозиторий: https://github.com/lazer361/mispisit-shortener
Ветка: lab4
Pull Request: https://github.com/lazer361/mispisit-shortener/pull/4
Образ: lazer361/mispisit-shortener:0.0.4
Страница образа: https://hub.docker.com/r/lazer361/mispisit-shortener

git clone -b lab4 https://github.com/lazer361/mispisit-shortener shortener
cd shortener
docker compose up -d
```

Открыть http://localhost:8080. В Compose используется готовый образ `lazer361/mispisit-shortener:0.0.4`, строки `build` нет. Имя проекта `mispisit-bezdnyakov` и том `dbdata` совпадают с третьей работой, поэтому прежние записи остаются доступными. Порт PostgreSQL наружу не публикуется.

## Локальная сборка

```sh
docker build -t shortener:0.0.4 .
docker compose up -d
```

Для проверки исходного кода можно собрать образ локально. Для обычного запуска используется опубликованный образ из Docker Hub.

## Интерфейс

Пользователь сервиса сам создаёт и просматривает ссылки. Выбран общий интерфейс в том же приложении. Отдельная административная панель и клиентский фронтенд для текущих действий не требуются. Из макетов прошлого семестра сохранены форма, список и карточка, уточнены размещение элементов и навигация. Авторизация, QR-коды, статистика и экспорт пока не реализованы.

Bootstrap 5.3.8 подключён локально из `static/vendor/bootstrap`. CSS и JavaScript включены в образ, CDN при открытии страниц не используется. JavaScript нужен для раскрытия мобильного меню. Лицензия находится рядом с файлами библиотеки. Версия и исходные файлы: https://getbootstrap.com/docs/5.3/getting-started/download/ .

| Адрес | Назначение |
|---|---|
| `/` | Главная с версией 0.0.4 |
| `/links/new` | Форма создания ссылки |
| `/links` | Общий список из PostgreSQL |
| `/links/1` | Карточка записи с идентификатором 1 |
| `/access-denied` | Пример отказа при неверном URL |
| `/s/study` | Переход по короткому адресу после создания имени study |

На всех страницах доступны общая навигация и номер версии. На узком экране меню сворачивается, записи списка показываются вертикально.

## Проверка

1. При первом запуске на новом томе открыть список: видны пояснение и кнопка создания первой ссылки. Если том уже использовался в третьей работе, список содержит прежние записи.
2. Создать ссылку через форму: URL `https://ulstu.ru/`, название `Учебный портал`, короткое имя `study`. Если такое имя уже занято, для новой записи выбрать другое.
3. Проверить сообщение об успешном создании, карточку и запись в списке. Короткий адрес перенаправляет на исходную страницу.
4. Повторить создание с тем же коротким именем: откроется `/access-denied?reason=alias_taken`, исходная запись останется без изменений.
5. Ввести URL `ulstu.ru` без протокола: откроется отказ с пояснением. Вернуться к форме и исправить адрес.
6. Проверить меню и страницы на узком экране.

Выполнены 14 автоматических проверок на каждой архитектуре, включая чтение и запись PostgreSQL, валидацию, уникальность кода и сохранение данных при повторном создании приложения. В браузере проверены пять страниц при ширине 1280 и 390 пикселей. ARM64 проверена через эмуляцию.

## Хранение и зависимости

Таблица `links`: `id`, `title`, `original_url`, `short_code`, `created_at`. Подключение задаётся через `DATABASE_URL`. Структура создаётся автоматически, демонстрационные записи не загружаются. Учебные логин, пароль и имя базы: `app`. Том смонтирован в `/var/lib/postgresql/data`.

Список общий, авторизация пока не реализована. Короткое имя содержит 3-32 латинские буквы, цифры, дефисы или знаки подчёркивания; регистр учитывается. Без имени код генерируется автоматически. Время показывается для Самары, UTC+4.

Python 3.12.12, Flask 3.1.3, Jinja2 3.1.6, Gunicorn 23.0.0, Psycopg 3.3.6. Версии Python-пакетов зафиксированы в `requirements.txt`. Образ собран для `linux/amd64` и `linux/arm64`; предыдущие теги не перезаписывались.
